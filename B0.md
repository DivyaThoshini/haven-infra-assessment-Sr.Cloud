# B0 — Get the service running

The `photo-api` service is supposed to run on a local Kubernetes cluster, but the manifests in
`k8s/` don't work. Get it running without changing anything under `service/`.

Done means: `kubectl -n haven get pods` shows the pod `1/1 Running`, and a request to the Service
returns the config JSON.

Setup and the exact commands are in `README.md`. Work only in `k8s/`.

Save the output of `kubectl -n haven describe pod -l app=photo-api` from before and after your
fixes in `TERMINAL_LOG.md`, and say in `B0.md` (below) what was wrong and how you found each
problem.

## What was wrong, and how I found it

1. Incorrect Readiness Probe

Issue: The Deployment used /health as the readiness probe endpoint. The application does not expose this endpoint.

Fix: Updated the readiness probe to /ready on port 8080.

Reason: The /ready endpoint returns HTTP 200 only after the application successfully loads its configuration from the Kubernetes ConfigMap.

2. Incorrect Liveness Probe

Issue: The Deployment used /health, which is not implemented by the application.

Fix: Updated the liveness probe to /healthz on port 8080.

Reason: The /healthz endpoint checks whether the application is alive.

3. Incorrect Service Target Port

Issue: The Kubernetes Service forwarded traffic to port 8081, while the application listens on port 8080.

Fix: Changed the Service targetPort to 8080, retaining Service port 80.

Reason: This ensures traffic reaches the application's actual listening port.

4. Missing Kubernetes RBAC Permissions

Issue: The application uses the photo-api ServiceAccount to retrieve the haven-config ConfigMap through the Kubernetes API. The original manifests did not define the required RBAC permissions.

Fix: Added k8s/rbac.yaml containing:

A namespace-scoped Role.

Permission to perform only the get operation on the haven-config ConfigMap.

A RoleBinding associating the Role with the photo-api ServiceAccount.

Reason: This follows the principle of least privilege and avoids granting unnecessary access.
